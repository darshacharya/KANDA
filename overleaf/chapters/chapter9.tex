\section{Key Findings}
\label{sec:key_findings}

Five results stood out during the project:

\begin{enumerate}[nosep]
  \item Commodity hardware suffices. Voice, vision, text reasoning, and motor control all run on parts totalling under \$77. No GPU, no custom training, no proprietary robotic platform. The ESP32 handles sensing and actuation; the Pi handles orchestration; the cloud handles heavy inference.

  \item No single safety layer is enough. Ablation showed distinct failure modes for each removed layer (\textbf{Table~\ref{tab:ablation_ch8}}). Prompt grounding prevents 15\% of unsafe plans; the validator catches 42\% of structurally bad outputs; the firmware reflex prevents 30\% of near-miss collisions. Remove any one, and a class of failures returns.

  \item Episodic memory transforms search. Without it, the robot revisited the same scene in 60\% of search steps, effectively halving its coverage. With the similarity threshold and adaptive lowering, zero revisits occurred across all successful trials.

  \item Scene descriptions in the prompt matter. Removing VLM descriptions from the body context increased forward-into-obstacle plans by 15\%. The model uses scene text to make navigation decisions that pure distance numbers alone cannot justify.

  \item The state machine keeps complexity manageable. Seven states with a global cancel mechanism made it possible to add wake-word detection, TTS, Telegram, and visual search without any of them blocking reflex handling or creating race conditions.
\end{enumerate}

\section{Engineering Reflections}
\label{sec:reflections}

Several design choices paid dividends beyond what I expected:

Newline-delimited JSON everywhere. One complete message per line, human-readable in any serial monitor. When half the integration bugs were swapped TX/RX wires or wrong baud rates, being able to read raw bytes in minicom saved hours. Adding the display-state field to telemetry later required zero protocol changes.

The cloud LLM is advisory, not authoritative. It suggests actions at roughly 0.3\,Hz. The firmware senses at 10\,Hz. Treating inference as a slow outer loop that the fast inner loop can override at any time eliminated an entire class of timing hazards. I never had to solve the ``what if the API hangs'' problem beyond a simple timeout.


Build the validator before the LLM client. I wrote and tested the safety validator in the first week of Phase~3, before the Groq client existed. This meant every subsequent prompt experiment was safe by construction; I could feed deliberately adversarial outputs to the validator and confirm that nothing dangerous passed. It also made switching from Gemini to Groq to NVIDIA a one-file change with no safety implications.


Incremental delivery. Phase~2 produced a working obstacle-avoidance robot with no Pi, no cloud, no AI. Phase~3 added intelligence on top of a known-good base. Phase~4 added multimodal inputs on top of a known-good intelligence layer. When something broke, the fault was always in the newest layer. This made debugging tractable on a two-person team.

\section{Limitations}
\label{sec:limitations}

KANDA has clear boundaries. Three ultrasonic sensors leave angular blind spots; objects at oblique angles go undetected. There is no odometry, so the robot has no metric position estimate. The single 3$\times$4\,m test room does not demonstrate scalability to larger environments. Cloud dependency means no reasoning without Wi-Fi. The wake-word model was tested only in quiet ($<$40\,dB) conditions. Ablation used $n{=}10$ per condition, which limits statistical power. And there was no inter-rater reliability check on intent labelling; both authors coded the same trials.

\section{Future Work}
\label{sec:future}

\begin{itemize}[nosep]
  \item On-device model: A quantised Gemma 2B or Phi-3 Mini on the Pi could provide sub-500\,ms inference without cloud dependency.
  \item Depth camera: An Intel RealSense or OAK-D Lite would replace ultrasonic blind spots with dense point clouds.
  \item Wheel encoders: Even simple optical encoders would enable dead-reckoning and allow the LLM to reason about distances travelled.
  \item SLAM: With a depth camera and encoders, lightweight visual SLAM could give the robot a map and enable ``go to the kitchen'' commands.
  \item Multi-room evaluation: Larger spaces with doorways, corridors, and dynamic obstacles would stress-test the search algorithm and safety layers.
  \item Formal verification: The validator is simple enough to prove correct with property-based testing or model checking against temporal safety policies.
\end{itemize}

\section{Closing Remarks}
\label{sec:ch9closing}

KANDA started as a question (can you make a \$77 robot that listens, sees, thinks, and avoids walls?) and ended as a working multimodal agent with 0.94 intent F1, 80\% visual search success, and zero sustained unsafe motion across all fault injections. The architecture is not novel in any single layer; what it contributes is the integration: a cloud LLM, a deterministic validator, and a firmware reflex, layered so that each compensates for the others' weaknesses, running on hardware cheap enough that a student can build one in a weekend.

If there is one takeaway from this project, it is that safety in embodied AI comes from structural separation of concerns, not from making the model smarter. The model will always hallucinate sometimes. The validator catches syntax. The firmware catches physics. Together they make the system trustworthy enough to let it drive around a room unsupervised.
